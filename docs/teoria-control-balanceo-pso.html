§0

El sistema y el banco de pruebas

Antes de cualquier ecuación conviene fijar qué hardware hace qué, y —más importante para no engañarse después— qué es lo que el banco de pruebas realmente permite validar y qué no.

0.1Reparto de responsabilidades

El sistema tiene tres actores con roles deliberadamente asimétricos:

  • ESP8266 — el cerebro. Lee el IMU por I²C, corre el filtro de fusión que estima el ángulo de inclinación (pitch), calcula la ley de control PID en tiempo real, ejecuta —fuera de línea, entre episodios— el optimizador PSO que ajusta las ganancias de ese PID, y además sostiene el stack de WiFi para telemetría y un panel de control. Todo el cómputo "inteligente" vive aquí.
  • Arduino Nano — el ejecutor. No decide nada. Recibe por UART una orden ya calculada (dirección + duty por rueda) y la traduce a PWM hacia el driver. Es, deliberadamente, el eslabón más simple y más predecible de la cadena — una decisión que en §7 se argumenta también como una decisión de seguridad, no solo de repartición de carga.
  • Driver de motores L298N + motores de rueda (JGB37-520B, 6V, 793RPM). Convierte PWM + dirección en el par que efectivamente mueve las ruedas contra el suelo.

0.2El banco de pruebas: ruedas en el piso, no péndulo colgante

Una decisión importante y fácil de subestimar: el robot se prueba con las ruedas apoyadas en el piso, no suspendido de forma que las ruedas giren libremente en el aire. La diferencia no es cosmética. Un montaje colgante elimina precisamente la dinámica que se quiere estudiar: la fricción rueda-suelo, la inercia real que hay que vencer para acelerar la base, y la zona muerta del actuador bajo carga real. Todo eso solo aparece con las ruedas tocando el piso — es el mismo argumento por el que la zona muerta de los motores debe medirse con carga real, no solo con las ruedas girando libres. La primera medición de este banco (duty≈77/255) se hizo en el piso, pero con ambos motores barridos a la vez, así que todavía no separa cuánto de ese umbral es fricción de rodadura real y cuánto es fricción de rodamientos común a ambas condiciones — un protocolo que mida los dos motores por separado, en el aire y en el piso, cierra esa pregunta (ver §9).

0.3Geometría del arnés de seguridad

El robot cuelga de una cuerda anclada a un punto fijo \(A\), a una altura \(h\) sobre el punto de sujeción del robot \(P\) cuando este está perfectamente vertical. La cuerda tiene holgura: su longitud real \(L = h+s\) es mayor que la distancia recta \(h\), de modo que no ofrece tensión durante el balanceo normal — solo debe tensarse cerca del límite de caída (\(\theta_\text{max}\approx 30°\)).

Para diseñar \(s\) con criterio —no "un poco de cuerda de más"— hace falta un modelo geométrico. Fijemos el eje de las ruedas en el origen y llamemos \(r\) a la altura del punto de sujeción \(P\) sobre ese eje. Con el robot inclinado un ángulo \(\theta\) (rotación rígida alrededor del eje de las ruedas, sin desplazamiento horizontal todavía):

\[ P(\theta) = (r\sin\theta,\; r\cos\theta), \qquad A = (0,\; r+h) \]

La distancia anclaje–sujeción es entonces

\[ d(\theta) = \sqrt{r^2\sin^2\theta + \big(h + r(1-\cos\theta)\big)^2} \]

y la cuerda se tensa exactamente cuando \(d(\theta) = h+s\). Para ángulos pequeños conviene una aproximación: expandiendo \(\sin\theta\) y \(\cos\theta\) a orden \(\theta^2\) y despreciando términos de orden superior,

\[ d(\theta) - h \;\approx\; \frac{r(r+h)}{2h}\,\theta^2 \]
Intuición

Con el anclaje justo arriba del punto de reposo, inclinar un poco el robot casi no aleja a \(P\) de \(A\) — el acercamiento es de segundo orden, como cuando un péndulo se aparta poco de su punto más bajo. Por eso una holgura chica alcanza para un rango angular sorprendentemente amplio antes de tensarse.

Este resultado es la justificación cuantitativa de "no ofrece tensión durante el balanceo normal": la longitud extra necesaria crece con \(\theta^2\), no linealmente, así que una holgura modesta cubre el rango de pitch normal de operación (unos pocos grados) sin acercarse a tensarse, y solo empieza a exigir longitud real cuando \(\theta\) se acerca al límite de diseño.

Ejemplo numérico — \(r=0.20\,\text{m}\), \(h=0.50\,\text{m}\)
Ángulo \(\theta\)\(d(\theta)-h\) exactoAproximación \(\theta^2\)
10°0.42 cm0.43 cm
20°1.68 cm1.71 cm
30° (límite)3.62 cm3.84 cm

Es decir: con \(r\approx20\,\text{cm}\) y \(h=50\,\text{cm}\), una holgura de apenas \(s\approx3.6\)–\(3.8\,\text{cm}\) basta para que la cuerda se mantenga floja hasta prácticamente el ángulo de caída, y se tense justo ahí. La aproximación cuadrática se desvía del valor exacto solo un 6% incluso a 30°, así que sirve bien para dimensionar la holgura de entrada — y luego se verifica y ajusta a mano, levantando el robot gradualmente y marcando dónde se tensa de verdad (ver la fila correspondiente en la tabla de fallas de §9).

0.4Qué valida el arnés, y qué no — honestamente

Hay una segunda restricción, independiente de la anterior, que importa aún más para diseñar el experimento: el anclaje es un punto fijo del piso, no algo que viaje con el robot. Si el robot se desplaza horizontalmente una distancia \(\Delta x\) manteniéndose vertical (\(\theta\approx0\)), la distancia anclaje–sujeción es simplemente \(d=\sqrt{\Delta x^2+h^2}\), y el mismo criterio de tensado da un desplazamiento horizontal máximo permitido:

\[ \Delta x_\text{max} = \sqrt{(h+s)^2 - h^2} = \sqrt{2hs+s^2} \]

Con los mismos números del ejemplo (\(h=0.50\,\text{m}\), \(s\approx0.038\,\text{m}\)), esto da \(\Delta x_\text{max}\approx0.195\,\text{m}\) — unos 20 cm de radio útil alrededor del punto de anclaje. Ese número, no el ángulo de 30°, es el que realmente acota qué se puede probar en este banco.

Lo que sí valida

El lazo de ángulo (el PID que mantiene \(\theta\approx0\)) con la dinámica de contacto rueda-piso real: fricción, zona muerta del actuador bajo carga, y perturbaciones dentro de un rango angular amplio (hasta cerca de 30°) con una red de seguridad real si algo sale mal.

Lo que no valida

Cualquier lazo de posición \(x\) que requiera desplazamientos mayores a ~20 cm del punto de anclaje, trayectorias largas, o navegación. Tampoco valida guiñada (yaw), terrenos irregulares, ni el comportamiento más allá de la zona de captura del arnés. Esta es, entre otras cosas, una de las razones por las que §3 pospone explícitamente el control en cascada de posición: no hay forma honesta de sintonizarlo ni validarlo en este banco todavía.

§1

Física del péndulo invertido

1.1Modelo de Lagrange (carro-péndulo)

El modelo canónico es un péndulo montado sobre una base que se puede acelerar horizontalmente. Sea \(x\) la posición horizontal de la base (controlada, en última instancia, por el par de las ruedas) y \(\theta\) el ángulo del cuerpo respecto de la vertical. Con \(M\) la masa efectiva de la base+ruedas, \(m\) la masa del cuerpo del robot concentrada en su centro de masa a distancia \(l\) del eje de las ruedas, e \(I\) el momento de inercia del cuerpo respecto de su propio centro de masa, la energía cinética y potencial son:

\[ T = \tfrac{1}{2}(M+m)\dot{x}^2 + m\,l\,\dot{x}\dot{\theta}\cos\theta + \tfrac{1}{2}(I+ml^2)\dot{\theta}^2, \qquad V = m g l \cos\theta \]

Aplicando las ecuaciones de Euler–Lagrange \(\frac{d}{dt}\frac{\partial \mathcal{L}}{\partial \dot q_i} - \frac{\partial \mathcal{L}}{\partial q_i}=Q_i\) sobre \(\mathcal{L}=T-V\) para \(q=(x,\theta)\), con \(F\) la fuerza horizontal neta que las ruedas aplican al suelo (reacción que empuja la base):

\[ \begin{aligned} (M+m)\ddot{x} + ml\ddot\theta\cos\theta - ml\dot\theta^2\sin\theta &= F \\[2pt] (I+ml^2)\ddot\theta + ml\ddot{x}\cos\theta - mgl\sin\theta &= 0 \end{aligned} \]

Este par de ecuaciones acopladas y no lineales es exacto, pero difícil de razonar a simple vista. Todo el trabajo de control ocurre cerca de \(\theta=0\), así que conviene linealizar.

1.2Por qué aparece un polo inestable

Para aislar la física esencial —y evitar cargar el álgebra completa de 4 estados—, conviene una simplificación estándar en estos análisis: tratar la aceleración de la base \(a=\ddot{x}\) directamente como la variable de control (es, salvo una constante, lo que las ruedas producen), y escribir el balance de torques del cuerpo alrededor del eje de las ruedas en el marco no inercial de la base, donde aparece una fuerza ficticia \(-ma\) actuando en el centro de masa:

\[ I_p\,\ddot\theta = mgl\sin\theta - mal\cos\theta, \qquad I_p \equiv I+ml^2 \]

(el teorema de ejes paralelos da \(I_p\), el momento de inercia respecto del eje de las ruedas). Esta expresión es algebraicamente consistente con las ecuaciones de Lagrange de arriba, y expone con claridad los dos términos en juego: gravedad, que crece con \(\sin\theta\) y siempre empuja alejando al péndulo de la vertical (desestabilizante), y control, la aceleración de la base, que puede contrarrestarla.

Linealizando en \(\theta\approx0\) (\(\sin\theta\approx\theta\), \(\cos\theta\approx1\)) y definiendo el estado \(z=[\theta,\dot\theta]^\top\):

\[ \dot\theta = \omega_0^2\,\theta - b\,a, \qquad \dot z = \underbrace{\begin{bmatrix}0 & 1\\ \omega_0^2 & 0\end{bmatrix}}_{A} z + \underbrace{\begin{bmatrix}0\\-b\end{bmatrix}}_{B} a, \qquad \omega_0^2=\frac{mgl}{I_p},\;\; b=\frac{ml}{I_p} \]

El polinomio característico de \(A\) es \(\lambda^2-\omega_0^2=0\), con raíces \(\lambda=\pm\omega_0\). Ahí está el resultado que importa: hay siempre un polo real positivo \(\lambda=+\omega_0\) —no un par complejo, no algo marginal— sin importar los valores concretos de \(m\), \(l\) o \(I_p\), en cuanto \(mgl>0\). Es un punto de equilibrio tipo silla: cualquier desviación crece exponencialmente sin intervención activa. Esto es, formalmente, la razón por la que "el equilibrio es inestable" no es una forma de hablar sino una propiedad algebraica del sistema linealizado.

Intuición

Un péndulo colgando hacia abajo tiene un polo imaginario puro (oscila, no crece). Invertirlo cambia el signo de un único término en la ecuación —el de gravedad— y ese cambio de signo convierte una oscilación eterna en una caída exponencial. Es literalmente la misma física con un signo distinto.

1.3Midiendo \(\omega_0\) sin descomponer una masa no homogénea

\(\omega_0=\sqrt{mgl/I_p}\) tiene unidades de \(\text{rad/s}\) y fija la escala de tiempo natural de la inestabilidad: \(\tau=1/\omega_0\) es el tiempo característico en el que una perturbación se multiplica por \(e\) si nadie interviene. El problema práctico es que \(m\), \(l\) (altura del centro de masa) e \(I_p\) son difíciles de estimar por separado en un chasis de tres niveles de madera con batería, placas y motores repartidos de forma no homogénea — cualquier descomposición pieza por pieza arrastra bastante incertidumbre.

Hay una salida que evita el problema por completo, en vez de intentar resolverlo. La misma \(I_p\) —momento de inercia respecto del eje de las ruedas— aparece sin cambios si, en lugar de pararse (equilibrio inestable), el robot cuelga libremente de ese mismo eje (equilibrio estable, un péndulo común). La única diferencia entre ambas configuraciones es el signo del término gravitacional: colgando, la ecuación linealizada es \(\ddot\theta=-\omega_0^2\theta\) (oscila); parado es \(\ddot\theta=+\omega_0^2\theta\) (diverge). La magnitud \(\omega_0\) es idéntica en los dos casos, porque depende de los mismos \(m\), \(g\), \(l\), \(I_p\) — nada de eso cambia si el cuerpo está arriba o abajo del pivote. El péndulo colgante oscila con período:

\[ T_\text{colgado} = \frac{2\pi}{\omega_0} \quad\Longrightarrow\quad \omega_0 = \frac{2\pi}{T_\text{colgado}} \]

Cronometrar cuánto tarda el robot en oscilar colgado del eje de las ruedas da \(\omega_0\) directamente — sin pesar cada nivel del chasis ni localizar el centro de masa. Basta con dejarlo oscilar libremente (empujón chico, 10–15°) y cronometrar varias oscilaciones completas —diez, para repartir el error de reacción al usar el cronómetro— y dividir. El propio giroscopio del Test 1 (ya operativo, reporta por WiFi) sirve para contar cruces por cero con más precisión que a ojo.

Medición pendiente en este proyecto

Esta medición todavía no se hizo — no hay un \(\omega_0\) real de este robot todavía, y no se inventa uno acá. Lo que sí puede calcularse sin ese dato es el umbral que le exige la regla de muestreo (10–20× la dinámica más rápida) a los 50 Hz que ya usa el Test 1: despejando, \(\omega_0\lesssim10\text{–}20\,\text{Hz}\times2\pi/10\approx15\text{–}31\,\text{rad/s}\) para tener margen. Es decir, \(\tau=1/\omega_0\gtrsim32\text{–}64\,\text{ms}\). El período colgante medido dirá si el robot real cae dentro de ese margen o si hace falta subir la tasa del lazo de control (no necesariamente la de reporte por WiFi) antes de cerrar el lazo, tal como se detalla en §7 con el timer de hardware.

1.4Ancho de banda alcanzable y fase no mínima

Hay un límite adicional, y este no se arregla subiendo la tasa de muestreo: cuando eventualmente se cierre un lazo externo de posición (mover el robot a un \(x\) deseado generando un ángulo de referencia pequeño para el lazo interno), la función de transferencia de la fuerza de las ruedas a la posición del carro —no al ángulo— tiene un cero en el semiplano derecho: es un sistema de fase no mínima.

La intuición física es directa: para acelerar hacia adelante, las ruedas primero tienen que inclinar el cuerpo hacia adelante, y para inclinarlo hacia adelante deben empujar momentáneamente hacia atrás. El robot "retrocede antes de avanzar" ante un comando de posición — un comportamiento característico de los ceros de fase no mínima, no un defecto de sintonía. Esto acota el ancho de banda máximo que cualquier controlador de posición puede alcanzar sin comprometer estabilidad, sin importar qué tan bien sintonizado esté. Es una limitación estructural de la planta, y una razón adicional —independiente de la del arnés en §0— para tratar el lazo de posición como un problema separado y posterior.

§2

Sensado y fusión de señales

2.1Qué mide cada sensor, y cómo falla

El acelerómetro no mide "inclinación": mide aceleración específica, la fuerza no gravitacional por unidad de masa a lo largo de cada eje. En reposo, sobre una masa de prueba que no acelera, la única fuerza no gravitacional es la normal del soporte, que exactamente cancela la gravedad — así que el acelerómetro "siente" \(-\vec g\) proyectada sobre sus ejes, y de ahí se puede recuperar el ángulo respecto de la vertical por trigonometría. El problema: si el robot además acelera linealmente (algo que un péndulo invertido corrigiendo su equilibrio hace todo el tiempo), esa aceleración se suma a la de gravedad y el cálculo de ángulo se contamina — el error no es ruido aleatorio, está correlacionado con el propio movimiento que se quiere controlar.

El giroscopio mide velocidad angular directamente, sin ser sensible a la aceleración lineal — pero integrar su lectura para obtener ángulo acumula cualquier sesgo (bias) de forma indefinida: un sesgo constante de solo \(0.5°/s\) integrado durante 10 s ya son \(5°\) de error acumulado, sin que el sensor esté "roto". Peor: ese sesgo no es una constante de fábrica, deriva con la temperatura y el tiempo de encendido.

Dato real de este proyecto

Por esta razón el bias del giroscopio se recalibra en cada arranque de cada sketch de prueba (promediando cientos de muestras con el robot quieto), en vez de hardcodearse como constante — es exactamente la consecuencia práctica de que el sesgo varía entre sesiones.

Los dos sensores fallan en bandas de frecuencia complementarias: el acelerómetro es confiable en continua/baja frecuencia (a largo plazo, sin aceleración neta, apunta bien "hacia abajo") pero ruidoso y sesgado por movimiento propio en alta frecuencia; el giroscopio es confiable en alta frecuencia (sin ruido de vibración lineal) pero deriva en baja frecuencia/continua. Esa complementariedad es, literalmente, de donde sale el nombre del primer filtro.

2.2Filtro complementario

La idea: pasar la estimación de ángulo del acelerómetro por un pasa-bajos, la del giroscopio integrado por un pasa-altos, y sumar — si ambas transferencias suman 1 en todo el espectro, el resultado no distorsiona una señal que estuviera perfectamente medida por ambos caminos a la vez. En su forma discreta más común:

\[ \hat\theta[k] = \alpha\big(\hat\theta[k-1] + \omega_\text{gyro}[k]\,\Delta t\big) + (1-\alpha)\,\theta_\text{accel}[k] \]

Deducción de \(\alpha\). En tiempo continuo, un pasa-bajos de primer orden con constante de tiempo \(\tau\) tiene \(H_\text{lp}(s)=\frac{1}{1+\tau s}\); su complemento —el pasa-altos con el mismo corte— es \(H_\text{hp}(s)=1-H_\text{lp}(s)=\frac{\tau s}{1+\tau s}\). Discretizando el pasa-bajos como un promedio móvil exponencial con período de muestreo \(\Delta t\), la correspondencia estándar entre la constante de tiempo continua y el coeficiente discreto es:

\[ \alpha = \frac{\tau}{\tau + \Delta t} \]

\(\tau\) es, en esencia, "cuánto tiempo confiar en el giro antes de dejar que el acelerómetro corrija". Con \(\tau=1\,\text{s}\) y un lazo a 200 Hz (\(\Delta t=5\,\text{ms}\)):

\[ \alpha = \frac{1}{1+0.005} \approx 0.995 \]

es decir, en cada paso el 99.5% del nuevo ángulo viene de integrar el giro, y solo el 0.5% de la lectura cruda del acelerómetro — suficiente para ir corrigiendo la deriva sin dejar que el ruido del acelerómetro contamine la estimación rápida.

Intuición

Es un crossover de parlantes: los graves (tendencias lentas, DC) van al woofer —el acelerómetro—; los agudos (cambios rápidos) van al tweeter —el giro integrado—. Cada altavoz reproduce solo la banda en la que suena bien.

2.3Filtro de Kalman — teoría completa

El complementario tiene un solo parámetro libre (\(\alpha\), equivalentemente \(\tau\)) elegido a mano, y asume que el bias del giro ya fue restado de antemano. El filtro de Kalman resuelve ambas limitaciones modelando explícitamente el bias como parte del estado y ponderando automáticamente, en cada paso, cuánto confiar en el modelo versus en la medida — según qué tan ruidosos sean uno y otra.

Modelo de espacio de estados

Estado: \(x=[\theta,\ \beta]^\top\), con \(\beta\) el sesgo (bias) del giro. El modelo de proceso dice que la velocidad angular real es la lectura cruda del giro menos su sesgo, y que el sesgo evoluciona como un paseo aleatorio lento:

\[ \dot\theta = \omega_\text{gyro} - \beta + w_\theta, \qquad \dot\beta = w_\beta \]

Discretizado con período \(\Delta t\), en forma matricial \(x[k]=Fx[k-1]+Bu[k]+w\):

\[ \underbrace{\begin{bmatrix}\theta\\ \beta\end{bmatrix}}_{x[k]} = \underbrace{\begin{bmatrix}1 & -\Delta t\\ 0 & 1\end{bmatrix}}_{F} \underbrace{\begin{bmatrix}\theta\\ \beta\end{bmatrix}}_{x[k-1]} + \underbrace{\begin{bmatrix}\Delta t\\ 0\end{bmatrix}}_{B}\,\omega_\text{gyro}[k] + w,\qquad w\sim\mathcal N(0,Q) \]

La medida es el ángulo que da el acelerómetro por trigonometría, \(z[k]=H x[k]+v\), con \(H=[1\;\;0]\) (el acelerómetro no observa el bias directamente) y \(v\sim\mathcal N(0,R)\) ruido de medida escalar.

Predicción y corrección

\[ \begin{aligned} \textbf{Predicción:}\quad & \hat x^-[k] = F\hat x[k-1] + Bu[k], \qquad P^-[k] = FP[k-1]F^\top + Q \\[8pt] \textbf{Corrección:}\quad & S[k] = HP^-[k]H^\top + R \\ & K[k] = P^-[k]H^\top S[k]^{-1} \\ & \hat x[k] = \hat x^-[k] + K[k]\big(z[k]-H\hat x^-[k]\big) \\ & P[k] = (I-K[k]H)\,P^-[k] \end{aligned} \]

Qué son \(Q\) y \(R\), y cómo se eligen en la práctica. \(R\) es la varianza del ruido de medida del acelerómetro — se mide directamente: con el robot quieto, se toman muchas muestras del ángulo derivado del acelerómetro y se calcula su varianza muestral. \(Q\) es la covarianza del ruido de proceso: \(Q_\theta\) grande dice "no confíes demasiado en integrar el giro, corrige rápido con la medida"; \(Q_\beta\) —normalmente mucho más chico, porque el sesgo cambia lento— dice qué tan rápido se le permite al filtro "creer" que el bias estimado cambió. En la práctica, \(R\) se mide y \(Q\) se ajusta empíricamente, partiendo de un orden de magnitud y observando el compromiso entre respuesta rápida (\(Q\) grande, más ruidoso) y suavizado con retardo (\(Q\) chico, más lento a seguir cambios reales).

Dato real de este proyecto

La calibración de este mismo IMU midió una desviación estándar de la magnitud de aceleración en reposo del orden de \(\sigma\approx0.02\)–\(0.04\,\text{m/s}^2\) según la corrida — ese es, directamente, el tipo de número del que se deriva \(R\) para el ángulo del acelerómetro (propagando esa varianza a través de la trigonometría del ángulo).

Por qué la ganancia de Kalman pondera automáticamente. Mirando la fórmula \(K=P^-H^\top S^{-1}\): si \(R\) es grande (medida muy ruidosa), \(S\) crece y \(K\) se achica — el filtro confía más en la predicción del modelo (integrar el giro) y casi ignora una medida puntual mala. Si \(Q\) es grande (poca confianza en el modelo), \(P^-\) crece y \(K\) aumenta — el filtro corrige agresivamente con cada medida nueva. A diferencia del complementario, esta ponderación no es un número fijo elegido una vez: se recalcula en cada paso a partir de las covarianzas, aunque en estado estacionario (cuando \(P\) converge a un valor constante) también termina siendo, en la práctica, casi constante — y de hecho puede demostrarse que el complementario de un polo es un caso límite del Kalman de este mismo modelo, en su ganancia de estado estacionario, para una elección particular de \(Q\) y \(R\). No son dos ideas distintas: son el mismo principio con distinto nivel de sofisticación.

Implementación de referencia (2 estados, medida escalar)

// Kalman 2 estados [theta, bias] para un robot balanceador.
// H = [1 0]; medida escalar => S es escalar, no hace falta inversion de matriz.
struct KalmanState {
  float theta = 0, bias = 0;
  float P[2][2] = {{1,0},{0,1}};
  float Q_theta = 0.001f, Q_bias = 0.003f, R_measure = 0.03f;
};

float kalmanUpdate(KalmanState& k, float gyroRate, float accelAngle, float dt) {
  // --- Prediccion ---
  k.theta += dt * (gyroRate - k.bias);

  k.P[0][0] += dt * (dt*k.P[1][1] - k.P[0][1] - k.P[1][0] + k.Q_theta);
  k.P[0][1] -= dt * k.P[1][1];
  k.P[1][0] -= dt * k.P[1][1];
  k.P[1][1] += k.Q_bias * dt;

  // --- Correccion (H = [1, 0], medida escalar) ---
  float S = k.P[0][0] + k.R_measure;
  float K0 = k.P[0][0] / S;
  float K1 = k.P[1][0] / S;

  float y = accelAngle - k.theta;   // innovacion
  k.theta += K0 * y;
  k.bias  += K1 * y;

  float P00 = k.P[0][0], P01 = k.P[0][1];
  k.P[0][0] -= K0 * P00;
  k.P[0][1] -= K0 * P01;
  k.P[1][0] -= K1 * P00;
  k.P[1][1] -= K1 * P01;

  return k.theta;
}

Este es, deliberadamente, un Kalman "desenrollado a mano" para 2×2 —sin librería de álgebra matricial—, el patrón estándar en implementaciones embebidas de este filtro para robots de balance, donde el estado es chico y fijo y no se justifica el costo de una librería genérica.

§3

Teoría del control PID en profundidad

3.1Significado físico de cada término

Con \(e(t)=\theta_\text{ref}-\hat\theta(t)\) (aquí casi siempre \(\theta_\text{ref}=0\)):

\[ u(t) = \underbrace{K_p\,e(t)}_{\text{rigidez}} + \underbrace{K_i\int_0^t e(\tau)\,d\tau}_{\text{memoria}} + \underbrace{K_d\,\dot e(t)}_{\text{amortiguamiento}} \]

P actúa como un resorte virtual: cuanto más inclinado, más fuerte empuja de vuelta, proporcional al error actual. I es memoria: acumula el error pasado y sigue empujando mientras quede algún error sostenido, eliminando el error estacionario que P solo no puede (un resorte ideal, sin fricción, se asienta con desviación residual si hay una carga constante que vencer). D anticipa: reacciona a la velocidad del error, frenando el movimiento antes de que llegue al punto de equilibrio, como un amortiguador.

3.2Forma discreta

Con período de muestreo \(\Delta t\), la forma "posicional" (calcula \(u\) completo cada vez) es la discretización directa de la integral y la derivada:

\[ u[k] = K_p\,e[k] + K_i\,\Delta t\sum_{j=0}^{k} e[j] + K_d\,\frac{e[k]-e[k-1]}{\Delta t} \]

Existe también la forma "de velocidad" o incremental, que calcula \(\Delta u[k]=u[k]-u[k-1]\) en vez de \(u[k]\) directamente — útil porque evita saltos bruscos al cambiar de modo de operación (por ejemplo, al pasar de lazo abierto a cerrado), ya que no depende de reconstruir el historial completo de \(e\).

3.3Patologías clásicas

Golpe derivativo (derivative kick)

Si el punto de referencia cambia de forma abrupta, \(e[k]-e[k-1]\) da un salto artificial que el término derivativo amplifica por \(K_d/\Delta t\) — un pico de control que no refleja nada físico, solo el cambio de referencia. La solución estándar es derivar sobre la medida, no sobre el error:

\[ D[k] = -K_d\,\frac{\hat\theta[k]-\hat\theta[k-1]}{\Delta t} \]

En este robot la referencia de ángulo es casi siempre \(0\) y rara vez cambia bruscamente, así que el golpe derivativo es menos crítico que en, por ejemplo, un lazo de temperatura con cambios de setpoint frecuentes — pero implementarlo correctamente de entrada cuesta lo mismo y evita sorpresas si más adelante se inyecta una referencia de ángulo pequeña desde un lazo de posición.

Derivada filtrada

La derivada pura amplifica ruido de alta frecuencia — cualquier salto entre dos muestras, real o no, se multiplica por \(1/\Delta t\), que a 200 Hz es un factor de 200. La forma estándar en implementaciones industriales es pasar el término derivativo por un filtro pasa-bajos de primer orden, parametrizado por una constante \(N\) (típicamente entre 8 y 20):

\[ D_f[k] = D_f[k-1] + \frac{\Delta t}{\Delta t + 1/N}\big(D[k]-D_f[k-1]\big) \]

\(N\) grande deja pasar más ruido pero responde más rápido; \(N\) chico filtra más pero introduce retardo de fase adicional — otro compromiso, no una elección libre de costo.

Windup del integrador y back-calculation

Cuando el actuador satura —en este robot, el PWM tiene un tope duro de 121/255, calculado para no superar los 6 V nominales del motor (JGB37-520B, 793RPM) con la batería a plena carga—, el error puede seguir siendo distinto de cero aunque el actuador ya no pueda responder más. El integrador sigue sumando ese error igual, y cuando la condición que causó la saturación termina, hay que "des-sumar" todo ese exceso antes de que el controlador vuelva a responder normalmente — produciendo sobreimpulsos grandes e innecesarios.

Back-calculation: en vez de dejar que el integrador acumule libremente, se le resta un término proporcional al exceso de saturación, con una ganancia de recuperación \(K_b\):

\[ I[k] = I[k-1] + K_i\,e[k]\,\Delta t + K_b\big(u_\text{sat}[k-1]-u_\text{unsat}[k-1]\big) \]

Mientras el actuador no satura, \(u_\text{sat}=u_\text{unsat}\) y el término extra es cero — el integrador funciona normal. En cuanto satura, el término empuja al integrador hacia el valor que sí sería consistente con el límite real del actuador, en vez de seguir inflándose sin sentido.

Zona muerta del actuador

Por debajo de cierto duty, el motor recibe tensión pero no vence su propia fricción estática — no gira. Es una no linealidad dura que ningún PID lineal compensa por sí solo: si el controlador pide un esfuerzo pequeño (que es exactamente lo que pide cerca del equilibrio, donde el error es chico), esa orden puede caer dentro de la zona muerta y no producir ningún movimiento real, aunque el cálculo del PID sea correcto.

Dato real de este proyecto

La zona muerta bajo carga real (robot en el piso, no en el aire) se midió en ~duty 77/255 — equivalente a unos 3.8 V promedio. Muy por debajo de eso el robot simplemente no respondía. La compensación estándar es una pre-distorsión: si el PID pide \(0<|u|<u_\text{zm}\), se reemplaza por \(\text{sign}(u)\cdot u_\text{zm}\), de forma que cualquier esfuerzo no nulo salte directo por encima del umbral de arranque real. M1 y M2 no se midieron por separado en esa corrida, así que en rigor la compensación debería tener dos umbrales, uno por motor, hasta confirmar si de verdad coinciden.

3.4Estructura en cascada, y por qué se pospone

El diseño natural para controlar también la posición \(x\) del robot es una cascada: un lazo externo lento compara \(x\) contra una referencia y genera un ángulo de referencia pequeño \(\theta_\text{ref}\) (inclinarse levemente hacia adelante para acelerar hacia adelante), que alimenta el lazo interno de ángulo ya descrito, mucho más rápido. Se pospone deliberadamente aquí por dos razones independientes ya establecidas: el lazo interno tiene que ser sólido y confiable antes de que valga la pena construir algo encima —un lazo externo amplifica cualquier debilidad del interno—, y el banco de pruebas actual, con el arnés de §0, no permite validar honestamente desplazamientos \(x\) más allá de ~20 cm del anclaje. No hay manera responsable de sintonizar el lazo externo todavía.

3.5Estabilidad: Routh–Hurwitz sobre la planta linealizada

Retomando el modelo de §1, \(\ddot\theta=\omega_0^2\theta-bu\), con un PID completo \(u=K_p\theta+K_d\dot\theta+K_i\sigma\) (\(\dot\sigma=\theta\), el estado integral) y con la convención de signos en que un duty positivo acelera las ruedas en el sentido que reduce \(|\theta|\), sustituir da:

\[ \dddot\theta \;\text{—en forma de estado, el polinomio característico del lazo cerrado es—}\quad s^3 + bK_d\,s^2 + (bK_p-\omega_0^2)\,s + bK_i = 0 \]

Para un polinomio cúbico \(s^3+a_2s^2+a_1s+a_0\), el criterio de Routh–Hurwitz da condiciones necesarias y suficientes de estabilidad: \(a_2>0\), \(a_1>0\), \(a_0>0\), y \(a_2a_1>a_0\). Aplicadas aquí:

\[ K_d>0,\qquad K_i>0,\qquad K_p>\frac{\omega_0^2}{b},\qquad K_d\Big(K_p-\frac{\omega_0^2}{b}\Big)>K_i \]

La tercera condición es la más reveladora: hay un umbral mínimo de \(K_p\), \(K_p^\text{min}=\omega_0^2/b\), por debajo del cual ningún valor de \(K_d\) o \(K_i\) puede estabilizar el sistema. No es una regla empírica de sintonía — sale directamente del álgebra. \(b=ml/I_p\) depende de la ganancia real motor-rueda (cuánta aceleración de base produce una unidad de esfuerzo de control), que no está medida todavía en este proyecto — se deja como parámetro libre a estimar experimentalmente antes de intentar predecir \(K_p^\text{min}\) con un número concreto, en vez de inventarlo.

Intuición

\(K_p\) tiene que "ganarle" a la gravedad antes de que valga la pena hablar de \(K_i\) o \(K_d\) — un resorte demasiado blando no sostiene nada, sin importar cuánto amortiguamiento o memoria se le agregue encima.

4.1Ziegler–Nichols de lazo cerrado (ganancia crítica)

Procedimiento clásico (1942): con \(K_i=K_d=0\), subir \(K_p\) gradualmente hasta que el sistema oscile con amplitud sostenida —ni crece ni decae—. Ese valor es la ganancia crítica \(K_u\); el período de esa oscilación es \(T_u\). Con ambos, la tabla original da:

(\(K_i=K_p/T_i\), \(K_d=K_p T_d\) para convertir a la forma paralela usada en §3.)

Por qué es arriesgado aplicarlo tal cual aquí

Z-N clásico apunta deliberadamente al borde de la oscilación sostenida, y su receta original tiende a dar ~25% de sobreimpulso — aceptable en un proceso industrial lento (temperatura, nivel de tanque), pero peligroso en un péndulo invertido real con un límite de caída a 30°: llevar el sistema a oscilación sostenida a propósito, en hardware físico, arriesga que la oscilación crezca más rápido de lo que da tiempo a medir \(T_u\) con precisión antes de que el arnés tenga que intervenir. Existen variantes "con menos sobreimpulso" de la tabla (p. ej. \(K_p=0.33K_u\)) más razonables como punto de partida aquí.

4.2Realimentación por relé (Åström–Hägglund)

Alternativa mucho más segura para plantas inestables u oscilatorias: en vez de subir \(K_p\) a ciegas, se reemplaza temporalmente el controlador por un relé de amplitud fija y pequeña \(d\) (con una pequeña histéresis para no reaccionar al ruido de medición): \(u=+d\) si \(e>0\), \(u=-d\) si \(e<0\). Esto induce automáticamente un ciclo límite —una oscilación de amplitud acotada por diseño, porque \(d\) se elige chico de antemano— sin necesidad de acercarse a ningún límite desconocido.

Se mide, del ciclo límite resultante, el período \(T_u\) y la amplitud de oscilación de la salida \(a\). Por análisis de descripción de función (el primer armónico de una onda cuadrada de amplitud \(d\) tiene magnitud \(4d/\pi\)), la ganancia última se estima como:

\[ K_u \approx \frac{4d}{\pi a} \]

y de ahí se aplican las mismas fórmulas de la tabla anterior. La ventaja concreta para este robot: el relé se implementa trivialmente reemplazando el cálculo de \(u\) del PID por la lógica bang-bang durante la rutina de sintonía, con \(d\) fijado deliberadamente chico (por ejemplo, equivalente a duty=30 — muy por debajo del cap de seguridad de 121) — oscilaciones pequeñas y controladas, apropiadas para un arnés que solo debería intervenir cerca de 30°, no en cada intento de sintonía.

4.3Procedimiento manual estructurado

Como alternativa o complemento, con criterios de parada objetivos en cada paso:

  1. Con \(K_i=K_d=0\), subir \(K_p\) hasta ver 2–3 oscilaciones visibles de baja amplitud tras una perturbación manual leve; retroceder a ~60–70% de ese valor.
  2. Agregar \(K_d\) gradualmente hasta que las oscilaciones se amorticen en menos de 1 ciclo visible tras la misma perturbación de referencia, sin agregar temblor audible del motor (señal de derivada sin filtrar amplificando ruido).
  3. Agregar el mínimo \(K_i\) necesario para que el robot no quede con una inclinación residual sostenida, vigilando que no reintroduzca oscilación de baja frecuencia (típico del windup si no hay back-calculation activo).

Función de costo / fitness

5.1Índices integrales clásicos

Índices de error integral
ÍndiceDefiniciónEfecto
IAE\(\int|e(t)|\,dt\)Lineal, robusto, no distingue errores grandes de chicos con énfasis.
ISE\(\int e(t)^2\,dt\)Penaliza fuerte los errores grandes; tiende a respuestas agresivas.

Para un péndulo invertido, cualquier perturbación produce inevitablemente un error inicial grande y breve — eso no es indicativo de mala sintonía. ITAE es la elección razonada aquí precisamente porque no castiga desproporcionadamente esa fase inicial, mientras sí penaliza fuerte cualquier error que persista en el tiempo, que sí es una señal confiable de mala sintonía (asentamiento lento, oscilación residual). Es, además, el índice más citado en la literatura de sintonía automática para plantas oscilatorias.

5.2Costo compuesto

Un fitness que solo mire el error de ángulo puede premiar controladores que "ganan" a costa de esfuerzo de control excesivo, cambios bruscos de duty (desgaste mecánico y eléctrico), o que se acercan peligrosamente al límite de caída. Un costo compuesto razonable:

\[ J = w_1\cdot\text{ITAE}(\theta) \;+\; w_2\int u(t)^2\,dt \;+\; w_3\int|\Delta u(t)|\,dt \;+\; w_4\cdot P_\text{caída} \]

donde \(\int u^2dt\) penaliza esfuerzo/energía, \(\int|\Delta u|dt\) penaliza chattering (cambios bruscos consecutivos de duty, que desgastan mecánicamente el driver y los motores), y \(P_\text{caída}\) es una penalización grande y fija si \(|\theta|\) supera el límite de seguridad o si el arnés llega a tensarse durante la corrida — un evento de falla que debe descalificar duramente esa configuración de ganancias, para que el optimizador de §6 aprenda a evitar esa región del espacio de búsqueda.

Un detalle que se pasa por alto seguido

ITAE, energía y chattering viven en escalas numéricas completamente distintas. Sumarlos con pesos \(w_i\) sin antes normalizar cada término por su rango típico observado hace que el término de mayor magnitud absoluta domine el costo total, sin importar qué tan cuidadosamente se elijan los pesos — un error común en implementaciones apuradas de PID+PSO.

5.3Arquitectura "dos programas, un solo fitness"

El plan de trabajo pide dos firmwares separados: uno con ganancias fijas (línea base, fruto de §4) que reporta \(J\), y otro que ajusta las ganancias vía PSO usando el mismo \(J\), para poder comparar de forma justa cuánto mejora el ajuste automático sobre el manual. Esa comparación solo es válida si el cálculo de \(J\) es exactamente el mismo código en ambos programas — no una reimplementación paralela que "debería" calcular lo mismo.

La razón no es estética: una diferencia sutil de implementación (orden de integración, ventana de tiempo distinta, redondeo) haría que cualquier "PSO mejora un X%" fuera, potencialmente, un artefacto de que las dos implementaciones del fitness no son idénticas — no una mejora real del control. La forma concreta de garantizarlo en firmware: un módulo único (por ejemplo fitness.h/fitness.cpp) compilado e incluido igual en ambos binarios, de forma que cualquier cambio al criterio de costo se propague automáticamente a los dos, o directamente rompa la compilación de ambos si hay una incompatibilidad — la sincronización queda forzada por construcción, no por disciplina manual de mantener dos copias iguales.

§6

Teoría de Particle Swarm Optimization

6.1Origen y ecuación fundamental

Kennedy y Eberhart lo propusieron en 1995, inspirados en el comportamiento social de bandadas de aves buscando comida: cada individuo ajusta su trayectoria combinando su propia experiencia con la información compartida del grupo, sin un líder central ni conocimiento del gradiente de la función que se optimiza. Cada "partícula" \(i\) es un candidato en el espacio de búsqueda —aquí, un vector \(x_i=[K_p,K_i,K_d]\in\mathbb{R}^3\)— con una posición y una velocidad que se actualizan en cada iteración:

\[ v_i[k+1] = w\,v_i[k] + c_1 r_1\big(p_i-x_i[k]\big) + c_2 r_2\big(g-x_i[k]\big), \qquad x_i[k+1]=x_i[k]+v_i[k+1] \]

con \(p_i\) el mejor punto que esa partícula visitó (memoria individual), \(g\) el mejor punto visitado por todo el enjambre (o su vecindad, ver 6.4), y \(r_1,r_2\sim U(0,1)\) independientes por dimensión y por iteración, que inyectan la estocasticidad necesaria para que las partículas no converjan por trayectorias idénticas y predecibles.

Rol de cada término
TérminoNombreEfecto
\(w\,v_i[k]\)InerciaMantiene la dirección previa; \(w\) alto = más exploración/momento.
\(c_1r_1(p_i-x_i)\)CognitivoAtracción hacia la mejor experiencia propia — "nostalgia".
\(c_2r_2(g-x_i)\)SocialAtracción hacia lo mejor encontrado por el grupo.

6.2El factor de constricción de Clerc–Kennedy

El PSO original, sin más ajuste, puede divergir: para ciertas combinaciones de \(w,c_1,c_2\) la varianza de la trayectoria de una partícula crece sin cota. Clerc y Kennedy (2002) analizaron la dinámica de una sola partícula —colapsando el término cognitivo y social en un único punto de atracción efectivo, técnica estándar en este tipo de análisis— como un sistema lineal discreto de segundo orden. Con \(\bar\varphi=c_1+c_2\), la recurrencia de la posición tiene el polinomio característico:

\[ \lambda^2 - (1+w-\bar\varphi)\lambda + w = 0 \]

Exigir que ambas raíces queden dentro del círculo unitario (criterio de Jury, el análogo discreto de Routh–Hurwitz) acota los valores admisibles de \(w\) y \(\bar\varphi\). Resolviendo esa condición para el caso \(\bar\varphi>4\), Clerc y Kennedy obtienen un factor de constricción \(\chi\) que, multiplicando toda la actualización de velocidad (no solo el término de inercia), garantiza convergencia:

\[ \chi = \frac{2}{\big|2-\varphi-\sqrt{\varphi^2-4\varphi}\big|}, \qquad \varphi=c_1+c_2>4 \]
Sobre el nivel de detalle

Se omite el desarrollo algebraico completo de cómo se llega a esa fórmula cerrada —es largo— y se presenta el resultado con su condición de aplicación y su origen conceptual (estabilidad de un sistema lineal de segundo orden), que es lo que hace falta para usarlo con criterio.

Con la elección canónica \(\varphi=4.1\) (típicamente \(c_1=c_2=2.05\)), \(\chi\approx0.7298\). Esta formulación de "constricción" y la más común de "peso de inercia decreciente" (\(w\) bajando linealmente de ~0.9 a ~0.4 durante la corrida, con \(c_1=c_2\approx2\) fijos) están algebraicamente emparentadas y son las dos variantes canónicas más usadas en la práctica.

6.3Exploración vs. explotación

\(w\) alto favorece exploración (las partículas cubren más espacio antes de comprometerse); \(w\) bajo favorece explotación (convergencia rápida hacia lo mejor conocido, con riesgo real de quedar atrapado en un óptimo local si ese "mejor conocido" no lo es globalmente). La estrategia más común —decrecer \(w\) linealmente durante la corrida— es, en esencia, empezar explorando y terminar explotando, sin tener que decidir de antemano cuál de los dos regímenes es "correcto".

6.4Topología: gbest vs. lbest

gbest: todas las partículas ven al mejor de todo el enjambre — converge más rápido, pero es más propenso a quedar atrapado en óptimos locales si el mejor global temprano resulta engañoso. lbest (anillo o vecindad): cada partícula solo ve al mejor de un subconjunto vecino — converge más lento pero es más robusto en superficies de costo multimodales.

Elección para este proyecto, con el trade-off explícito

Cada evaluación de fitness aquí implica correr un episodio físico completo de varios segundos en hardware real — no es una función analítica gratis de evaluar miles de veces como en simulación. Eso empuja a enjambres pequeños (6–10 partículas, no las 20–50 típicas en literatura de simulación) y a topología gbest simple, priorizando converger con menos evaluaciones totales por sobre la robustez extra de lbest — una decisión de costo experimental, no de preferencia algorítmica abstracta.

6.5Manejo de fronteras

El espacio de búsqueda debe acotarse a rangos físicamente sensatos de \([K_p,K_i,K_d]\) —por ejemplo, un rango de ±50–100% alrededor del resultado de §4—. Si una partícula sale de ese rango, las estrategias estándar son reflejar (rebotar la velocidad), absorber (fijar la posición al límite y anular la velocidad en esa dimensión), o reinicio aleatorio dentro del rango. Aquí conviene absorber con velocidad amortiguada: cruzar el límite superior de \(K_p\) o \(K_d\) en este robot no es un evento abstracto — significa probar, en hardware físico real, ganancias que ya se consideraron potencialmente peligrosas al definir el rango. El manejo de fronteras es, aquí, una medida de seguridad tanto como una decisión matemática.

6.6Funciones de costo ruidosas

Muchas implementaciones de PSO asumen implícitamente que evaluar la misma posición dos veces da el mismo valor de fitness. Eso es falso cuando el fitness se mide en hardware real: ruido de sensor, variación de fricción entre corridas, y una perturbación manual que nunca es exactamente repetible hacen que el mismo \([K_p,K_i,K_d]\) pueda dar valores de \(J\) distintos en corridas sucesivas.

Fuente concreta de ruido no estacionario en este robot

El cap de PWM (121/255) se calculó asumiendo 12.6 V fijo como peor caso de una LiPo 3S llena. Durante una sesión larga de PSO, el voltaje real de la batería cae progresivamente por debajo de ese peor caso — el mapeo duty→voltaje real cambia lentamente a lo largo de la sesión sin que el firmware lo sepa. No es que las ganancias mejoren o empeoren: es que la planta cambió sutilmente bajo los pies del optimizador.

Mitigaciones estándar: promediar 2–3 evaluaciones por partícula antes de aceptar un fitness (a costa de tiempo experimental proporcional); mantener el \(p_\text{best}\) con cierta tolerancia en vez de reemplazo estricto ante cualquier mejora marginal (para no anclarse en una medición favorablemente ruidosa); y re-evaluar periódicamente el \(g_\text{best}\) para confirmar que sigue siendo, de verdad, el mejor.

6.7Criterios de parada

Número fijo de iteraciones (predecible en tiempo total de banco, importante cuando cada evaluación cuesta minutos, no milisegundos); falta de mejora del \(g_\text{best}\) durante \(K\) iteraciones seguidas (estancamiento); o, más pragmático dado el costo real de cada corrida, un presupuesto total de tiempo de banco de pruebas fijado de antemano.

6.8PSO frente a otras alternativas sin gradiente — comparación honesta

Nelder–Meadsimplex

Determinista, mantiene un simplex de \(n+1\) puntos (4, para 3 parámetros) y lo deforma —reflexión, expansión, contracción— buscando mejorar el peor vértice.

+ Muchas menos evaluaciones por iteración que un enjambre completo — una ventaja real cuando cada evaluación cuesta tiempo de hardware.

− Mucho más propenso a atascarse en óptimos locales, y las comparaciones estrictas "mejor/peor" entre vértices son frágiles frente al ruido de medición — sin memoria social que amortigüe una evaluación puntual mala.

Optimización bayesianaproceso gaussiano

Construye un modelo probabilístico de \(J(K_p,K_i,K_d)\) a partir de lo ya evaluado, y elige el siguiente punto maximizando una función de adquisición (p. ej. mejora esperada).

+ Extremadamente eficiente en número de evaluaciones — a menudo converge en 15–30 evaluaciones totales en 3 dimensiones, el recurso más escaso en este banco.

− Mucho más complejo de implementar embebido (álgebra de procesos gaussianos, inversión de matrices de covarianza creciente); en la práctica correría mejor en una PC recibiendo telemetría por WiFi, no dentro del ESP8266.

Conclusión honesta: si el objetivo fuera minimizar puramente el número de pruebas físicas necesarias, optimización bayesiana probablemente le gana a PSO en eficiencia muestral. PSO se justifica en este proyecto por tres razones concretas y no por ser "el más popular": cabe entero en el ESP8266 sin dependencias numéricas pesadas, tolera razonablemente el ruido de medición gracias a su memoria acumulada de \(p_\text{best}\)/\(g_\text{best}\) —a diferencia de Nelder-Mead, que depende de comparaciones puntuales—, y tiene un paralelismo conceptual natural si en el futuro hubiera más de un robot idéntico evaluando partículas distintas en simultáneo (no es el caso hoy, pero es una ventaja estructural real del algoritmo, no hipotética).

Arquitectura de firmware concreta

7.1El lazo de control no puede vivir en un loop() bloqueante

El ESP8266 tiene un solo núcleo, y su stack de WiFi (parte del SDK subyacente, no de la lógica de la aplicación) necesita que se le ceda tiempo de CPU periódicamente mediante llamadas internas de "fondo". Si el loop() principal se queda bloqueado demasiado tiempo (por ejemplo con delay() largos dentro del propio lazo de control), el watchdog interno del SDK puede resetear el chip — y aún sin llegar a ese extremo, un delay() cuya duración real varía según qué esté haciendo el stack de WiFi en ese instante introduce jitter en el período de muestreo, y un PID discreto asume implícitamente un \(\Delta t\) aproximadamente constante.

La solución estándar: un timer de hardware (en el core Arduino de ESP8266, la librería Ticker o el timer1 de bajo nivel) que dispara a una tasa fija e independiente de lo que haga el resto del programa. Dentro de la interrupción, el patrón más seguro no es hacer todo el trabajo pesado ahí mismo —leer I²C dentro de una ISR es delicado, puede competir con otras interrupciones o tardar más que el margen disponible—, sino simplemente levantar una bandera; el trabajo real (leer IMU, fusionar, calcular PID) se hace en el loop() principal, al inicio de cada vuelta, si la bandera está activa.

// Patron recomendado: ISR minima + bandera + trabajo diferido en loop()
#include <Ticker.h>
Ticker controlTimer;
volatile bool controlTick = false;

void IRAM_ATTR onControlTimer() {
  controlTick = true;  // nada mas: nada de I2C, nada de calculo pesado aqui
}

void setup() {
  // 200 Hz -> 5000 us
  controlTimer.attach_ms(5, onControlTimer);
}

void loop() {
  if (controlTick) {
    controlTick = false;
    runControlStep();      // IMU + fusion + PID + envio UART, aqui si
  }
  server.handleClient();   // WiFi / dashboard, sin bloquear
}

7.2Protocolo UART: dos canales sobre un enlace

Un canal de texto de baja tasa, legible para debug humano (líneas ASCII cada varios cientos de ms), conviviendo con un frame binario compacto para la orden de PWM, enviado a la tasa completa del lazo de control. El Nano es deliberadamente "tonto": no debería tener que parsear texto con algo como sscanf a 200 Hz —más caro computacionalmente y con jitter propio—, así que la orden de control va en un frame binario de tamaño fijo:

Frame binario de orden de PWM — 5 bytes
ByteContenido
00xAA — byte de sincronismo
1banderas de dirección (bit7=M1, bit6=M2, resto reservado)
2duty motor 1 (uint8, 0–121)
3duty motor 2 (uint8, 0–121)
4checksum (XOR de los bytes 1–3)

5 bytes a 200 Hz son 1000 bytes/s de datos útiles — cómodo incluso a 57600 baudios, con margen de sobra para intercalar el canal de texto. El checksum simple (XOR) alcanza para que el Nano descarte un frame corrupto sin necesitar un CRC más pesado de calcular en un microcontrolador de 8 bits.

El protocolo no sirve de nada si daña al ESP8266 primero

Hay un problema eléctrico previo a cualquier frame: el Nano corre su lógica a 5V, y su pin TX saca un "1" a ~5V. El ESP8266 opera a 3.3V y sus GPIO no toleran 5V — es un límite del silicio, no de la alimentación (que sí puede compartirse: ambos chips tomando 5V del mismo riel lógico no es el problema). Meter 5V directo al RX del ESP8266 puede dañarlo de forma permanente. La dirección opuesta (ESP TX a 3.3V → Nano RX) no necesita nada: 3.3V ya supera el umbral de "1 lógico" de un ATmega328 a 5V, con margen modesto pero suficiente.

La solución estándar para la línea Nano TX → ESP RX es un divisor resistivo simple —dos resistencias, sin chip adicional—: \(R_1=1\text{k}\Omega\) entre el TX del Nano y un nodo medio, \(R_2=2\text{k}\Omega\) entre ese nodo y GND, y el RX del ESP8266 conectado al nodo medio.

\[ V_\text{out} = 5\,\text{V}\times\frac{R_2}{R_1+R_2} = 5\times\frac{2}{3}\approx3.33\,\text{V} \]

Dentro del rango seguro del ESP8266 (nominal 3.3V, máximo absoluto ~3.6V). La resistencia \(R_1\) en serie con la línea, junto con la capacitancia parásita del cable, forma un pasa-bajos con constante de tiempo del orden de decenas de nanosegundos — varios órdenes de magnitud menor que un bit a 115200 baudios (~8.7 µs), así que no distorsiona la señal a esta velocidad. Esta pieza no está en el inventario del proyecto todavía; hasta que se arme y se verifique con multímetro, el Test 4 (validación del enlace UART) sigue sin correrse — no por falta de diseño, sino porque conectar el Nano TX directo al ESP RX antes de tener el divisor puesto sería exactamente el error que este apartado describe.

7.3Seguridad: el Nano como última línea de defensa

Que el Nano "no decida nada" no es solo una repartición de carga computacional — es, además, la razón por la que puede actuar como chip de seguridad independiente. Si el ESP8266 se cuelga, se resetea, o simplemente deja de enviar frames (por un bug del stack WiFi, o porque una configuración de ganancias propuesta por PSO hizo que el lazo divergiera tan rápido que el ESP quedó ocupado en otra cosa), el Nano debe notarlo por su cuenta y llevar los motores a parada segura, sin depender de que nadie se lo ordene:

// En el Nano: watchdog de frames UART
unsigned long lastFrameMs = 0;
const unsigned long FRAME_TIMEOUT_MS = 100;  // ~20 periodos de lazo a 200 Hz

void loop() {
  if (readValidFrame(&dutyM1, &dutyM2, &dirFlags)) {
    lastFrameMs = millis();
    // segunda linea de defensa: el Nano tambien aplica el cap, no confia ciegamente en el ESP
    dutyM1 = constrain(dutyM1, 0, 121);
    dutyM2 = constrain(dutyM2, 0, 121);
    applyMotors(dutyM1, dutyM2, dirFlags);
  }

  if (millis() - lastFrameMs > FRAME_TIMEOUT_MS) {
    applyMotors(0, 0, 0);  // parada segura, sin esperar permiso
  }
}

El cap de PWM aplicado en ambos extremos (ESP al calcular, Nano al ejecutar) es defensa en profundidad, el mismo patrón que ya usa el sketch de prueba de motores de este proyecto real (constrain() dentro de setMotor(), no confiado a que el valor recibido ya venga bien). Adicionalmente, el ESP debería cortar el lazo de control y forzar duty=0 si \(|\hat\theta|\) supera un umbral de seguridad (por ejemplo 25°, con margen antes de los 30° del arnés) — en ese punto, dejar que el arnés físico haga su trabajo es preferible a que el motor siga "luchando" con ganancias potencialmente mal sintonizadas.
